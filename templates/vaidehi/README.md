# Vaidehi — reference-guided Indian wedding invitation

A reusable member of PAIGAAM's existing bfday template family. This is not an external app, new platform or separate publishing system. The only shared registration change is the new slug in templates/bfday.js. No database migrations, platform UI rewrites, payment changes, or wedding-video changes.

## Routes after deployment

- /templates/vaidehi — existing template detail flow
- /create/vaidehi — existing six-step editor and live preview
- /vaidehi/demo — Rohan Malhotra & Kiara Shah sample
- /vaidehi/preview-frame — existing stateless preview
- /api/vaidehi/draft, /upload, /upload-audio and /publish — existing family APIs
- /p/vaidehi-… — existing published invitation URLs

The config seeds a new listing at INR 99 as explicitly requested. An owner can change its commercial price in Admin. Existing prices are never overwritten by this template. The release catalogue thumbnail is a real 1000×688 two-scene capture at /vaidehi/catalog-thumbnail.webp; the designed portrait share-card fallback remains /vaidehi/thumbnail.webp. No live payment or production deployment is implied.

## Content and inheritance

config.js is the editor specification and demo; schema.js validates customer data; render.js is a server-rendered document; public/vaidehi/invite.css and invite.js provide the layout and progressive enhancement. Fields are generated by the existing shared editor, not a second form implementation.

All personal names, family names, messages, dates, times, venue details, Maps URL, QR destination and images come from validated customer_data. The demo alone contains sample identities and generated fictional photographs. A new customer is not assigned those photographs or names. Keep explicit empty gallery/event arrays empty rather than restoring sample content.

- weddingDay is optional: blank derives the real weekday from weddingDate.
- Blank event date uses the wedding date plus editable dayOffset; blank event time uses the main wedding time. Blank event venue fields inherit the main venue. The sample Wedding Ceremony has no duplicate date/time; sample Reception inherits the wedding date, with its independent 20:30 time. Haldi/Mehendi use dayOffset -1 (17 February in the sample), so changing the wedding date moves them too. Enter an explicit event date to override the relative offset.
- Blank mapsUrl searches Google Maps for the current venue and address. A nonblank URL is an intentional override, so clear it when changing venue if it should not remain fixed.
- Per-event directions inherit the global URL only when the entire venue is inherited. Overriding a venue derives a new address query unless the customer explicitly supplied event mapsUrl.
- Blank qrDestination follows the effective main Maps URL. QR is generated on the server by the existing local QR encoder; no third-party QR service receives customer details. Dense QR codes expand to preserve scannability on phones. Publishing rejects an effective URL over 2000 UTF-8 bytes; a lenient draft preview explains when a shorter destination is needed.
- Blank countdownDate/countdownTime follow weddingDate/weddingTime independently. utcOffset defaults to +05:30, and is editable. Date/time calculations are deterministic for guests in any timezone. The countdown stops at zero with a celebration message. An optional countdownPhoto replaces the reference hands illustration with a personal wedding portrait.
- couplePhoto is added to the gallery unless already present. Gallery supports up to 12 photos; events support up to 20 reorderable cards. Venue details expand with accessible native details/summary controls to retain the reference's compact timeline.
- Uploaded background music only. No autoplay before a user gesture. Guests have play/pause controls and an error message if media is unavailable. No song is shipped or licensed by this template.

## Reference and fidelity

The input is a 24.07-second, 720×1280 filmed tablet walkthrough, not a source design or a screen capture. The visible continuous scroll, cream paper, marigolds, banana leaves, serif/script pairing, stacked tilted Polaroids, right-hand temple/banana/lamp composition, venue QR and faded garden, alternating timeline, joined wedding hands and countdown are reconstructed in that order. The opening PAIGAAM screen is required by the brief but is not actually visible in the recorded excerpt.

The initial artwork was newly generated from the filmed visual references. The first Save the Date cover has since been revised using individual transparent/cropped assets extracted from the user-supplied, text-free still: waist-down attire and red knot, two marigold/jasmine chains, two banana-leaf corners, blank paper and individual rose petals. It is not one flattened invitation background, and no personal text is baked into any image. All other artwork is unchanged. Fonts are locally hosted OFL Cormorant Garamond and Great Vibes, close substitutes, not a verified identification of the original typefaces. The illustrations, faces, exact grain, transition curves and proportions cannot be claimed pixel-identical. Full fictional names wrap more than the short names in the recording. Photos are fictional AI-generated sample people, never represented as real customers. The garden is ornamental, not a factual photograph of Aarohi Gardens. The sample countdown retains the illustrated hands visible in the actual recording; an uploaded wedding photograph is supported. Small accessible navigation, gallery controls and expandable venue details add working controls without replacing the scroll experience. See REFERENCE.md for the timestamp observations and QA.md for actual verification.

## Assets

node scripts/prepare-vaidehi.js restores checksum-verified packed WebP artwork and locally hosted fonts, including four uniquely named demo images under /assets/bfday-demo/vaidehi-demo-N.webp. npm build and postinstall call this preparer. No external image/font/QR runtime services are needed. Text remains real, selectable HTML; no names/dates/messages are baked into pictures. OFL licenses are in public/vaidehi/fonts. Generated media is ignored by git and restored from assets/vaidehi/manifest.json and its base64 files. Do not commit all of public/assets: other templates may restore their own files during local testing.
